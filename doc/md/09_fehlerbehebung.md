# 9. Fehlerbehebung

Die folgende Tabelle enthält eine Übersicht über häufig auftretende Fehler und ihre Behebung:

| Problem | Lösung |
|---------|--------|
| "Es konnten keine Schlüsselzahlen ermittelt werden!" | Widersprüchliche Vorgaben überprüfen. Laufzeit erhöhen. Feste Vorgaben reduzieren. |
| "Inkonsistenter Spielplan"-Meldung | Heim-/Auswärtsspielvorgaben für das genannte Team überprüfen. Sicherstellen, dass Teams desselben Vereins in derselben Spielwoche kompatible Vorgaben haben. |
| Schlüsselzahlen bei Referenzrasteränderung zurückgesetzt | Das ist erwartetes Verhalten. Die Schlüsselzahlen der Spielwochen, deren Referenzraster geändert wurde, passen nicht mehr zum Raster und werden bei allen Vereinen auf 0 zurückgesetzt; eine Meldung nennt die betroffenen Vereine. Tragen Sie dort bei Bedarf neue Schlüsselzahlen ein. |
| Fehlermeldung "Die Gruppe enthält noch Mannschaften. Bitte löschen Sie zunächst diese!" beim Löschen einer Gruppe | Eine Gruppe kann nur gelöscht werden, wenn sie keine Mannschaften mehr enthält; es wird nichts gelöscht. Entfernen Sie im Fenster "Dateninput" zunächst alle Mannschaften aus der Gruppe und löschen Sie danach die Gruppe (siehe [4.2 Manueller Datenimport: Gruppentabelle](04_datenimport.md#linke-seite-gruppentabelle)). |
| Fehlermeldung "Der Verein hat noch Mannschaften in den Gruppen …" beim Löschen eines Vereins | Ein Verein kann nur gelöscht werden, wenn keine seiner Mannschaften mehr einer Gruppe zugeordnet ist; es wird nichts gelöscht. Die Meldung nennt die betroffenen Gruppen. Löschen Sie zunächst die Mannschaften des Vereins aus diesen Gruppen und danach den Verein (siehe [4.2 Manueller Datenimport: Vereinstabelle](04_datenimport.md#mittlere-seite-vereinstabelle)). |
| Fehlermeldung "Die Gruppe … ist voll (Raster …). Es kann keine weitere Mannschaft hinzugefügt werden." | Die Gruppe enthält bereits so viele Mannschaften, wie ihre Rastergröße zulässt; die Mannschaft wird nicht hinzugefügt. Erhöhen Sie zunächst die Rastergröße der Gruppe (siehe [4.2 Manueller Datenimport: Gruppentabelle](04_datenimport.md#linke-seite-gruppentabelle)) und fügen Sie die Mannschaft anschließend hinzu. |
| Fehlermeldung "Ungültige Eingabe: Der Teamname muss mit dem Vereinsnamen (…) beginnen!" beim Umbenennen einer Mannschaft | Der neue Teamname beginnt nicht mit dem Namen des Vereins; die Eingabe wird automatisch zurückgesetzt. Behalten Sie den Vereinsnamen am Anfang des Teamnamens bei (z.B. "Borussia Duesseldorf II", siehe [4.2 Manueller Datenimport: Mannschaftstabelle](04_datenimport.md#rechte-seite-mannschaftstabelle)). |
| Eingetragene Vereins-Schlüsselzahl wird nicht übernommen | Die Zahl liegt außerhalb des Referenzrasters der Spielwoche (also nicht zwischen 1 und der Rastergröße des Referenzrasters A/B bzw. X/Y) und wird abgewiesen. Tragen Sie eine Zahl aus diesem Bereich ein (siehe [4.2 Manueller Datenimport: Vereinstabelle](04_datenimport.md#mittlere-seite-vereinstabelle)). |
| Fehlermeldung beim Klick auf **OK** im Fenster "Alternativen" | Es gibt noch ungelöste Konflikte (eine Schlüsselzahl ist in einer Gruppe mehrfach vergeben, auch an eine Mannschaft außerhalb des Konflikts) oder eine Mannschaft hat keine Schlüsselzahl. Die Meldung nennt die betroffenen Mannschaften, und das Fenster bleibt geöffnet. Weisen Sie die Schlüsselzahlen so zu, dass jede Mannschaft eine Schlüsselzahl hat und jede Schlüsselzahl in der Gruppe nur einmal vergeben ist, und klicken Sie erneut auf **OK** (siehe [6.1 Konflikte beheben](06_generierung.md#61-konflikte-beheben)). |
| Frage "Wollen Sie die Konfliktauflösung wirklich verlassen? Es bleiben ungelöste Konflikte." beim Schließen des Fensters "Alternativen" | Das ist erwartetes Verhalten: Beim Schließen des Fensters (über **Abbrechen** oder das Schließen-Symbol) wird stets nachgefragt. Mit **Ja** wird die Konfliktauflösung beendet; die verbliebenen Konflikte können später über **Sonstiges** → **Konflikte neu auflösen** aufgelöst werden. Mit **Nein** bleibt das Fenster geöffnet. |
| Frage "Wollen Sie die Änderungen speichern?" beim Schließen des Fensters "click-tt Import" oder "Dateninput" | Das ist erwartetes Verhalten: Seit dem letzten Speichern wurden Daten importiert oder geändert. Wählen Sie **Ja**, um die Änderungen zu speichern, **Nein**, um sie zu verwerfen, oder **Abbrechen**, um im Fenster zu bleiben. Ohne ungespeicherte Änderungen schließt das Fenster ohne Rückfrage (siehe [4.1 Import aus Click-TT](04_datenimport.md#41-import-aus-click-tt) und [4.2 Manueller Datenimport](04_datenimport.md#42-manueller-datenimport)). |
| Button "Generieren" ist nicht aktiviert | Stellen Sie sicher, dass Daten geladen oder importiert wurden. |
| Buttons für Datenimport sind nicht aktiviert | Stellen Sie sicher, dass beide Referenzraster eingestellt sind. |
| Fehlermeldung "Das Referenzraster … wird von der aktuellen Konfiguration nicht unterstützt" beim Laden einer Datei | Die Datei verwendet ein Referenzraster, für das die aktuelle Konfiguration keinen Spielplan enthält. Importieren Sie die Konfiguration, mit der die Datei erstellt wurde (siehe [7.5 Konfiguration exportieren und importieren](07_sonstige_funktionen.md#75-konfiguration-exportieren-und-importieren)), und laden Sie die Datei erneut. |
| Fehlermeldung "Die Konfiguration ist ungültig" beim Programmstart oder Konfigurationsimport | Die geladene Konfigurationsdatei enthält ungültige Werte (z.B. leere Altersklassen, widersprüchliche Rastergrößen oder fehlerhafte Spielplan-Einträge). Die Fehlermeldung listet die konkreten Verstöße auf. Exportieren Sie über **Sonstiges** → **Konfiguration exportieren** eine gültige Konfiguration und verwenden Sie diese als Vorlage. |
